## 1. Overview
Wakeel AI utilizes a microservices architecture:
*   **.NET 10 Backend:** Manages RBAC, business logic, persistence (SQL Server), file storage, and acts as the API Gateway.
*   **Node.js AI Service:** Manages LLM orchestration (LangChain), RAG pipelines (MongoDB Atlas), vector embeddings, and AI chat persistence.

The API enforces Tenant Isolation: every authenticated request carries a `company_id` inside its JWT, and every query on the backend must filter by that `company_id`.

4. AI Assistant (API Gateway Pattern)The .NET backend does not execute AI orchestration. These endpoints act as an API Gateway: .NET intercepts the JWT, extracts user identity, resolves/generates the conversationId, and proxies the payload securely to the Node.js AI Service using the internal M2M contract.  4.1 conversationId LifecycleClient sends POST /chat/ask with no conversation_id -> this is a new conversation.  .NET generates a new conversationId (UUID) and includes it in the body it sends to POST /api/ai/chat on the AI Server.  .NET returns that identifier to the client as conversation_id in the response.  The client includes conversation_id on every subsequent POST /chat/ask and on GET /chat/history for that thread.  All history and ownership are scoped by conversationId + userId + companyId on the AI Server side.  4.2 Ask the assistantPOST /chat/ask (HR Manager, Employee)
